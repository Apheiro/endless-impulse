# Desktop settings

Settings provides **Monitors**, **Windows & effects** and **Keyboard & mouse**.
It reads the current compositor state asynchronously. Editing controls only changes
a shared draft. Test changes, then keep or revert them within 20 seconds.

Monitors can be dragged in the diagram, positioned relative to another display or
edited with logical coordinates. While dragging a display, the page does not scroll.
`MonitorGeometry.js` sweeps its logical rectangle against other enabled displays,
blocking overlap and fast jumps through them while allowing sliding along edges.
The diagram uses rotated, scaled dimensions and writes only the draft on release.
Resolution and refresh rate come from advertised
modes. Scale must produce whole logical pixels; rotation and reflection are supported.
Device controls write only fields explicitly edited; unchanged values remain inherited.

## Persistence and integration

- `$XDG_CONFIG_HOME/endless-Impulse/hyprland.json`: confirmed overrides, version 1.
- `$XDG_CONFIG_HOME/endless-Impulse/hyprland.lua`: generated Lua, including a
  temporary candidate during a preview. Do not edit this file by hand.
- `$XDG_STATE_HOME/endless-Impulse/desktop/`: transaction, previous Lua,
  session/deadline marker, recovery log, lock and integration backups.
- `hypr/hyprland/services/desktop.lua`: loader called last by `hyprland.lua`.

The helper's `install` action backs up the active entry point, installs the loader
and appends only its require line. It never rewrites monitor or personal settings
files. Without integration, the pages remain readable and offer an enable button.
The normal dotfiles installer includes the loader and entry-point call.

## Recovery

A detached Python process owns the rollback deadline. It restores the previous
managed file, reloads the personal configuration and restores the previously active
monitor geometry and affected global options. Removing an override exposes the
original configuration again; it never deletes the original rule.

The Lua loader checks the preview session and deadline before loading a candidate.
After logout, crash or reboot, unconfirmed settings cannot become the next session's
layout. The next helper call reconciles the pending transaction. Restoration uses
a CLI-safe Lua expression so its leading comment cannot be parsed as hyprctl
flags. A failed restoration preserves the baseline as `restore_failed`, stops
automatic attempts and exposes an explicit retry. Recovery logs stay in the state
directory. Repeating Revert after the guard already restored is harmless.

From a terminal or TTY, an active preview can also be reverted without finding its token:

```bash
python3 src/quickshell/scripts/hyprland/desktop.py recover
```

Run this from the repository with the same user and Hyprland session environment.
Normal commands are `snapshot`, `preview` (JSON on stdin), `confirm TOKEN`,
`revert TOKEN`, `transaction`, `install` and the internal `watch TOKEN`.
Mutations are serialized; only confirmed JSON is treated as saved preferences.

## Verification

`./dev check` includes typed payload and Lua checks, read-only snapshots, temporary
preview/confirmation, expiration, detached rollback after the initiating command
exits, retry after IPC failure and a new-session Lua-loader check. All writes and
IPC mutations in these tests use temporary directories and a simulated compositor.
The settings navigation test loads every page with representative controls and
checks that opening them leaves the draft empty. Real mode changes remain a manual
hardware acceptance test.

The action bar stays fixed above the scrolling content of the monitor, window and
input pages. It remains available across categories while a draft or preview is
pending. Revert/confirm dismiss the separate preview prompt while resolving; active
previews synchronize across Settings instances.
Resolution clicks queue behind in-flight queries and dismiss the prompt
immediately. Failed responses still synchronize transaction state; neither the
countdown nor the detached guard loops on a failed restoration. These rules apply
to Monitors, Windows & effects, and Keyboard & mouse through `DesktopSettings`.

Border colors use Qt Quick ColorDialog with alpha support, editable gradient stops
and a 0–360° angle. Manual Hyprland RGBA syntax remains available. Color selection
updates only the desktop draft until Test changes and Keep changes are used.
